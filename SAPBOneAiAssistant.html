Clean Architecture Principles

Isolation of business rules from UI, database, and frameworks. This structure ensures that the system is testable, independent of technical details, and highly maintainable.

Design Patterns & SOLID

Dependency Inversion Principle (DIP)

High-level code depends on abstractions, not concrete implementations. This decouples our Application from the specific AI provider or database provider.

// Domain declares what it needs: public interface ILlmClient { Task<string> GenerateAsync(string prompt, string? model = null); } // Infrastructure provides implementation: public sealed class OllamaClient : ILlmClient { ... } // Mock used in unit testing: var llm = Substitute.For<ILlmClient>(); llm.GenerateAsync(...).Returns("fake response");
🗄

Repository Pattern

Decouples persistence from business logic, allowing us to swap databases (SQLite to SQL Server) without changing a single line of Application code.

1Define IConversationRepository
2Implement SqliteConversationRepository
3Inject into ChatService via DI

Domain-Driven Design

Using Entities (identities) and Value Objects (data-defined) to model the SAP business domain accurately.

→ ChatSession (Entity)
→ SapIntent (Value Object)
→ ConversationContext

Inversion of Control

All dependencies are supplied automatically at runtime using ASP.NET Core's built-in container.

AddScoped AddSingleton AddTransient

Ingestion Phase

{}

1. Document Parsing

Using Ollama's local embedding models to convert text into high-dimensional numerical vectors.

Persisting embeddings in SQLite with indexing for fast k-nearest-neighbor (k-NN) retrieval operations.

Retrieval Phase

🔍

1. Semantic Querying

The system converts the user's question into a vector and searches the database for text with similar mathematical intent.

📋

2. Contextual Prompting

Retrieved chunks are injected into the system prompt, providing the LLM with relevant ground truth data.

Accuracy Guarantee

Technical Core Components

Mathematical Model

Cosine Similarity

Our RAG engine calculates the dot product of two vectors divided by the product of their magnitudes. This measures the cosine of the angle between them, where 1.0 indicates perfect semantic alignment.

similarity = (A · B) / (||A|| ||B||)
